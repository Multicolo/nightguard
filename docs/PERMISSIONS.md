# 权限：要开哪些、怎么进、锁不干净怎么办

NightGuard 不是系统级 kiosk（没有设备管理员/无障碍），它靠三件事把界面「顶」在最上层：

1. **前台服务**一直活着（通知 + 电池白名单）；
2. 到点用 **`startActivity`** 拉起全屏 `LockActivity`（需要悬浮窗权限，Android 才允许后台拉起界面）；
3. 被 Home / 别的 App 顶掉后，服务在 **2 秒内**再拉一次。

所以权限开得越全，「锁」越接近关不掉。App 设置页里有一个**权限检查清单**，点每一行会跳到对应系统页面。

---

## 1. 显示在其他应用上层（悬浮窗）—— **必需**

没有它，后台 `startActivity` 会被系统静默拦截，到点什么都弹不出来。

- App 内：设置页 →「⚠️ 悬浮窗（必需）—— 点这里开启」→ 打开开关。
- 手动：**设置 → 应用 → 特殊应用权限 → 显示在其他应用上层 → 守夜鱼 → 允许**
  （Android 13/14 在「应用 → 特殊应用权限」；部分 ROM 叫「悬浮窗」「在其他应用上层显示」）。
- adb（调试）：

```bash
adb shell cmd appops set com.nightguard.app SYSTEM_ALERT_WINDOW allow
adb shell appops get com.nightguard.app SYSTEM_ALERT_WINDOW   # 确认
```

## 2. 通知（Android 13+）—— **必需**

前台服务必须挂一条常驻通知；通知权限被关，部分系统会直接把服务判为「不可见」并限制后台拉起。

- App 内：第一行「⚠️ 通知（前台服务）」→ 允许。
- 手动：**设置 → 通知 → 守夜鱼 → 允许通知**。
- Android 12 及以下没有这个运行时权限，跳过即可。

## 3. 电池优化白名单 —— 推荐

不加的话，息屏一段时间后系统可能冻结服务（尤其国产 ROM 的「智能省电」「深度睡眠」）。

- App 内：设置页 →「电池优化白名单」→ 允许。
- 手动：**设置 → 电池 → 电池优化 → 所有应用 → 守夜鱼 → 不优化**
  （部分 ROM：**设置 → 应用 → 守夜鱼 → 电池 → 无限制 / 允许后台活动**）。

## 4. 自启动 / 后台弹出 —— 推荐（国产 ROM 必看）

这一项没有统一 API，App 会按品牌依次尝试打开对应页面；打不开就退回「应用详情」，需要你手动找。

| 品牌 | 页面路径（大致） |
| --- | --- |
| 小米 / Redmi（MIUI、HyperOS） | 设置 → 应用设置 → 应用管理 → 守夜鱼 → **自启动** 打开；**省电策略 → 无限制**；**其他权限 → 显示在其他应用上层 / 锁屏显示** 打开；最近任务里给 App「加锁」 |
| 华为 / 荣耀（EMUI、HarmonyOS） | 设置 → 应用 → 应用启动管理 → 守夜鱼 → 关闭「自动管理」→ 允许**自启动 / 关联启动 / 后台活动** |
| OPPO / 一加（ColorOS） | 设置 → 应用 → 自启动管理 → 允许守夜鱼；电池 → 更多设置 → 睡眠待机优化 → 关闭 |
| vivo / iQOO（OriginOS） | 设置 → 应用与权限 → 权限管理 → 自启动 → 允许；后台高耗电 → 允许 |
| 三星（One UI） | 设置 → 电池 → 后台使用限制 → 把守夜鱼加入「永不休眠的应用」 |
| 原生 Android / Pixel | 一般只需 1–3 项；「设置 → 应用 → 守夜鱼 → 电池 → 无限制」 |

## 5. 锁屏显示（部分 ROM）—— 可选

要在**锁屏状态下**也直接显示聊天框（而不是解锁后才弹），部分 ROM 还要单独允许：

- 小米：应用管理 → 守夜鱼 → 其他权限 → **锁屏显示**
- 华为/荣耀：应用启动管理里允许「后台活动」后通常即可
- 其他：设置里搜「锁屏显示」「后台弹出界面」

代码里已经调用了 `setShowWhenLocked(true)` / `setTurnScreenOn(true)`，系统允许的话会直接盖在锁屏上。

## 怎么确认真的生效

```bash
# 权限
adb shell cmd appops get com.nightguard.app SYSTEM_ALERT_WINDOW
adb shell dumpsys deviceidle whitelist | grep nightguard

# 守夜是否在跑（前台服务）
adb shell dumpsys activity services com.nightguard.app | grep GuardService

# 现在最上层是谁（应该锁屏时是 .LockActivity）
adb shell dumpsys activity activities | grep -i topResumedActivity
```

手动测试：App 里点「立即锁一次」，然后依次按 **Home**、打开 **设置**、按 **返回**，
每次都应该在 2 秒内回到聊天框；`ps -A | grep nightguard` 里进程一直在（说明只是压后台、没杀进程）。

## 锁不干净的常见原因

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 到点完全不弹 | 没有悬浮窗权限 / 服务被冻结 | 开第 1、3 项；确认通知没被关 |
| 按 Home 后不回来 | 自启动/后台弹出被拦，或省电策略杀了服务 | 开第 3、4 项；最近任务里给 App 加锁 |
| 息屏一会儿就失效 | 电池优化没加白名单 | 第 3 项 + 关闭「睡眠待机优化」 |
| 锁屏上不显示，解锁才弹 | 缺「锁屏显示」权限 | 第 5 项 |
| 通知栏没有常驻通知 | 通知权限被关 | 第 2 项 |
| 强退 App 就没了 | 这是软锁的边界 | 见下 |

## 为什么是「软锁」

普通 App 想做到真正关不掉，只有两条路：

1. **Device Owner / 设备管理员**（企业 MDM 那套）：需要恢复出厂后重新配置设备，个人手机代价太大；
2. **无障碍服务**：能更强地拦截，但权限极重、商店审核严格，也容易被用户自己关掉。

NightGuard 选择了「全屏 Activity + 2 秒回弹」：不需要重权限，日常防熬夜够用，
但**开发者选项强退、安全模式、系统级弹窗**仍能绕过。这是设计取舍，不是 bug。
